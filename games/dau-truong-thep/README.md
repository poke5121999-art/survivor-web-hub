# Đấu Trường Thép

Real-time top-down 5v5 mech arena shooter. three.js r160 (vendored), ES modules, no build step, no asset files: geometry, textures and sound are generated by code.

## Layout

| File | Owns |
|---|---|
| `js/data.js` | Every tunable as tables: `MECHS`, `RULES`, `PICKUPS`, `PROPS`, `DIFFICULTY`, `TEAMS`, `REWARDS` |
| `js/maps.js` | Hand-written map layouts, `compileMap`, collision queries (`solidAt`, `castStatic`, `losClear`), `findPath` |
| `js/sim.js` | The match simulation. Pure, deterministic, 30 Hz. `createMatch`, `step`, `visibleTo`, `hidden`, `unitSpeed`, `summary` |
| `js/bots.js` | `botInput(m, u)`: one input per bot per tick. Pure, uses only `m.rng` for randomness |
| `js/main.js` | Boot, shared state `G`, main loop, URL params, test hooks |
| `js/gfx/*.js` | Renderer: textures, world, mechs, effects, post chain |
| `js/audio.js` | Synthesised sound and music |
| `js/ui.js`, `js/input.js`, `js/keys.js`, `js/meta.js`, `css/ui.css` | HUD, menus, garage, lobby, input devices (keyboard, mouse, touch, gamepad), key bindings, save data |
| `js/net/`, `js/netstate.js`, `js/online.js` | Online play: Unity Relay rooms (copied from Blockade Z, tag `dauthep`), snapshots and mirror match, lobby and host/guest state machine |
| `tools/` | Node and Playwright checks |

## Rules that keep it testable and ready for online play

- `sim.js`, `maps.js`, `bots.js`, `data.js`, `rng.js` never import three.js or touch the DOM. They run in Node.
- All randomness in a match comes from `m.rng`. Same seed and same inputs give the same match.
- The renderer, audio and HUD only read match state and `m.events`. They never write to it.
- Angles are radians in the XZ plane, direction = `(cos a, sin a)`. +x is right on screen, +z is toward the camera (down on screen).

## Simulation contract

```js
const m = createMatch({ map: 'denrung', seed, roster });   // roster: [{ team: 0|1, mech, name, bot, diff, mods: { hp, dmg }, paint }]
step(m, inputs);                                           // inputs[unit.id] = input
// input = { mx, mz, aim, fire, s1, s2, ult, heal, tx, tz }
//   mx, mz: move vector (-1..1)     aim: radians     tx, tz: world point under the cursor (ground-targeted skills)
//   fire, s1, s2, ult, heal: booleans, held is fine (cooldowns gate them)
```

Match `m`: `map, tick, time, target, duration, score[2], over, winner (-1 draw), units[], shots[], zones[], crates[], props[], events[]`.

Unit `u`: `id` (= index in `m.units`), `team, mech, def (MECHS row), name, bot, diff, radius, x, z, px, pz (previous tick), vx, vz, aim, heading, hp, maxHp, alive, respawnT, cd {fire, s1, s2, ult, heal}, shield, shieldMax, shieldT, slowT, slowF, stunT, hasteT, rapidT, dmgT, stealthT, invulnT, revealT, bush (-1 or bush id), cast (null or {skill, t, total, aim}), dash, kills, deaths, assists, dmg, healed, brain (free for bots.js)`.

Shot: `id, team, owner, x, z, px, pz, dx, dz, speed, left (range left), dmg, splash, r, vis`.

Zone: `id, kind ('strike' | 'mine' | 'field' | 'dome' | 'wall' | 'turret'), team, owner, x, z, r, age, delay, dur`, plus `total`, `lob`, `x0`, `z0` (strike; a lobbed weapon shell is a strike with `lob`), `blast` (mine), `vis` ('heal' | 'slow' | 'smoke' | 'blizzard' | 'magnet'), `hide`, `pull` (field), `pts[[x, z]]` (wall: circles of radius `r` that block movement and shots), `hp`, `maxHp`, `aim`, `range` (turret).

Crate: `id, x, z, type (PICKUPS key), fall (> 0 while descending), age`.

Events (`m.events`, valid until the next `step`): `fire {id, vis, x, z, a, side}`, `skill {id, slot, skill, x, z, a}`, `impact {vis, on: unit|wall|prop|dome|end, x, z, dx, dz, splash}`, `hit {id, by, x, z, amt, absorbed}`, `heal {id, x, z, amt}`, `death {id, by, assists[], x, z}`, `respawn {id, x, z}`, `explode {x, z, r, why}`, `nova {id, x, z, r}`, `beam {id, x0, z0, x1, z1, w}`, `ram`, `shieldBreak`, `item {id}`, `zone`, `zoneEnd`, `propHit`, `propBreak {id, kind, x, z}`, `crateDrop {id, x, z, type}`, `crateLand`, `pickup {id, crate, type, x, z}`, `turretFire {id, zone, x, z, a}`, `over {winner}`.

Skill primitives (`do`): `shield, dash, blink, nova (windup, optional repeat/gap), beam, volley, buff (haste, rapid, stealth), barrage (disc or line), mine, minefield, zone (field: hps, dps, slow, hide, pull), dome, recoil, wall, turret`. Weapons are shots (`n` pellets with `fan`, optional `slow`) or lobbed strikes (`lob`, `flight`).

Map (`m.map`): `key, name, w, d, hw, hd, walls[{x0, x1, z0, z1, h, kind}], rounds[{x, z, r, kind}], bushes[{id, x, z, r}], props, cratePoints, bases[2] = [x, z], spawns[2], nav`.

## Modes, themes, online

- Modes are rows in `MODES` (`tdm`, `nha`, `chiem`, `tudo`, `trum`); `createMatch({ mode })`. `nha` adds `m.towers`, `chiem` adds `m.points`, `trum` adds `m.lives` and a `BOSSES` unit, `tudo` gives every unit its own team. `u.color` (0 or 1) is the palette index the renderer and HUD use.
- A theme (`THEMES` in `maps.js`) dresses any layout and decides what the layout's hazard spots are (`lava`, `ice`, `vent`, `mud`). `createMatch({ map, theme })`; `pickArena(map, theme, seed)` resolves `'random'`.
- Online is host-authoritative: the host steps the real match, guests send inputs and render a mirror match built by `createMirror` and updated by `applySnapshot` (15 Hz, events in between). `?fakenet=1` swaps the relay for a BroadcastChannel.

## Shared state `G` (browser)

`G = { THREE, params, quality, bus, renderer, scene, camera, match, me, meta, audio, ui, input, gfx }`

- `G.bus.on(topic, fn)`, `G.bus.emit(topic, data)`. Topics: `sim` (each sim event, payload = event), `match:start`, `match:over`, `ui:play {mech, diff, map}`, `ui:menu`, `quality:set`.
- `G.match` is the current match or null. `G.me` is the id of the player's unit.
- `G.project(x, y, z)` → `{ x, y, visible }` in CSS pixels. `G.groundAt(clientX, clientY)` → `[x, z]` on the ground plane.
- `G.portrait(mechKey, team)` → data URL of a rendered mech portrait (128 px).

## URL params and test hooks

`?autostart` (skip menus, start a match), `?noaudio`, `?q=low|medium|high`, `?seed=N`, `?bots=easy|normal|hard`, `?mech=key`, `?map=key|random`, `?theme=key|random`, `?mode=key`, `?fakenet=1`, `?spectate` (the player slot is a bot too), `?manual` (the loop does not advance by itself; use `__step`).

`window.__G`, `__ready`, `__errors[]`, `__stats {fps, ms, calls, tris, quality, scale}`, `__step(n, draw)` (advance n sim ticks, draw one frame if `draw`), `__setShot({x, z, dist, pitch, yaw} | null)` (pose the camera), `__input(fn | object | null)` (scripted player input: `fn(m, u) → input`), `__start(choice, attract)` (start a match).

## Tools

| Tool | What it proves |
|---|---|
| `node tools/sim-test.mjs` | Rules of the simulation and the bots, in Node: hits, walls, bushes, every skill, airdrops, respawn, match end, determinism, hard beats easy |
| `node tools/play.js` | The real page in headless Chrome: full bot matches at every quality tier, scripted player input, HUD, result screen, saved rewards, menu, keyboard and mouse, phone layout |
| `node tools/audio.js` | Every synthesised sound and music stem: no NaN, no clipping, levels, event coverage |
| `node tools/ui-shots.js` | HUD, menu, garage, lobby, key binding, gamepad and chat screens in a harness at desktop and phone sizes (about 5 minutes) |
| `node tools/netstate-test.mjs` | Snapshot → mirror equals the real match in every mode; events replay in order; snapshot size |
| `node tools/online-test.js` | Host and two guests in a harness over `?fakenet=1`: lobby, start, inputs, leave, chat |
| `node tools/lobby-test.js` | Two real game pages over `?fakenet=1`: create, join by code, pick, start, play, result, back to the room |
| `node tools/relay-live.js` | Three pages over the REAL Unity Relay: join by list and by code, one full co-op match, same score and result everywhere. Run with `DTT_BASE` on the deployed hub |
| `node tools/bench.js [tiers] [phone]` | Frame cost per quality tier in a busy fight |
| `tools/shot.js`, `sheet.js`, `lineup.js`, `thumb.js` | Screenshots for review sheets (`.chk/`) and the hub card |

Browser tools need `PLAYWRIGHT_PATH`. `DTT_GL=gl-egl` uses the hardware GPU, `DTT_BASE=<hub url>` runs against a deployed hub.
