# Đấu Trường Thép

Real-time top-down mech arena shooter, 1v1 to 3v3 (3v3 by default). three.js r160 (vendored), ES modules, no build step, no asset files: geometry, textures and sound are generated by code.

## Layout

| File | Owns |
|---|---|
| `js/data.js` | Every tunable as tables: `MECHS`, `RULES`, `PICKUPS`, `PROPS`, `DIFFICULTY`, `TEAMS`, `REWARDS` |
| `js/maps.js` | Hand-written map layouts, `compileMap`, collision queries (`solidAt`, `castStatic`, `losClear`), `findPath` |
| `js/sim.js` | The match simulation. Pure, deterministic, 30 Hz. `createMatch`, `step`, `visibleTo`, `hidden`, `unitSpeed`, `summary` |
| `js/bots.js` | `botInput(m, u)`: one input per bot per tick. Pure, uses only `m.rng` for randomness |
| `js/main.js` | Boot, shared state `G`, main loop, URL params, test hooks |
| `js/camera.js` | The camera rig: follow, aim pan, the half-turned view for team 1, death and spectate, minimap look. Pure, runs in Node |
| `js/gfx/*.js` | Renderer: textures, world, mechs, effects, post chain |
| `js/audio.js` | Synthesised sound and music |
| `js/ui.js`, `js/input.js`, `js/keys.js`, `js/meta.js`, `css/ui.css` | HUD, menus, garage, lobby, input devices (keyboard, mouse, touch, gamepad), key bindings, save data |
| `js/net/`, `js/netstate.js`, `js/predict.js`, `js/online.js` | Online play: Unity Relay rooms (copied from Blockade Z, tag `dauthep`) and region choice, wire format and mirror match, prediction of the guest's own mech, lobby and host/guest state machine |
| `tools/` | Node and Playwright checks |

## Rules that keep it testable and ready for online play

- `sim.js`, `maps.js`, `bots.js`, `data.js`, `rng.js` never import three.js or touch the DOM. They run in Node.
- Every playable mech moves as the same circle (`RULES.moveRadius`, `u.moveRadius`), so an opening lets all of them through or none; `u.radius` is the size shots and rams hit. A layout edit must leave `tools/gaps.mjs` with no tight or false opening.
- All randomness in a match comes from `m.rng`. Same seed and same inputs give the same match.
- The renderer, audio and HUD only read match state and `m.events`. They never write to it.
- Angles are radians in the XZ plane, direction = `(cos a, sin a)`. +x is right on screen, +z is toward the camera (down on screen), unless the view is turned half round (see "Camera"): then both are mirrored, and only `input.js`, `touch.js` and the minimap know.

## Simulation contract

```js
const m = createMatch({ map: 'denrung', seed, roster });   // roster: [{ team: 0|1, mech, name, bot, diff, mods: { hp, dmg }, skin }]
step(m, inputs);                                           // inputs[unit.id] = input
// input = { mx, mz, aim, fire, s1, s2, ult, heal, tx, tz }
//   mx, mz: move vector (-1..1)     aim: radians     tx, tz: world point under the cursor (ground-targeted skills)
//   fire, s1, s2, ult, heal: booleans, held is fine (cooldowns gate them)
```

Match `m`: `map, tick, time, target, duration, score[2], over, winner (-1 draw), units[], shots[], zones[], crates[], props[], events[]`.

Unit `u`: `id` (= index in `m.units`), `team, mech, def (MECHS row), name, bot, diff, radius, x, z, px, pz (previous tick), vx, vz, aim, heading, hp, maxHp, alive, respawnT, cd {fire, s1, s2, ult, heal}, shield, shieldMax, shieldT, slowT, slowF, stunT, hasteT, rapidT, dmgT, stealthT, invulnT, revealT, bush (-1 or bush id), cast (null or {skill, t, total, aim}), dash, kills, deaths, assists, dmg, healed, brain (free for bots.js)`.

Shot: `id, team, owner, x, z, px, pz, dx, dz, speed, left (range left), dmg, splash, r, vis`.

Zone: `id, kind ('strike' | 'mine' | 'field' | 'dome' | 'wall' | 'turret'), team, owner, x, z, r, age, delay, dur`, plus `total`, `lob`, `x0`, `z0` (strike; a lobbed weapon shell is a strike with `lob`), `blast` (mine), `vis` ('heal' | 'slow' | 'smoke' | 'blizzard' | 'magnet'), `hide`, `pull` (field), `pts[[x, z]]` (wall: circles of radius `r` that block movement and shots), `hp`, `maxHp`, `aim`, `range` (turret).

Crate: `id, x, z, type (PICKUPS key), fall (> 0 while descending), age`.

Events (`m.events`, valid until the next `step`): `fire {id, vis, x, z, a, side}`, `skill {id, slot, skill, x, z, a}`, `impact {vis, on: unit|wall|prop|dome|end, x, z, dx, dz, splash}`, `hit {id, by, x, z, amt, absorbed}`, `heal {id, x, z, amt}`, `death {id, by, assists[], x, z}`, `respawn {id, x, z}`, `explode {x, z, r, why}`, `nova {id, x, z, r}`, `beam {id, x0, z0, x1, z1, w}`, `ram`, `shieldBreak`, `item {id}`, `zone`, `zoneEnd`, `propHit`, `propBreak {id, kind, x, z}`, `crateDrop {id, x, z, type}`, `crateLand`, `pickup {id, crate, type, x, z}`, `turretFire {id, zone, x, z, a}`, `over {winner}`.

Skill primitives (`do`): `shield, dash, blink, nova (windup, optional repeat/gap), beam, volley, buff (haste, rapid, stealth), barrage (disc or line), mine, minefield, zone (field: hps, dps, slow, hide, pull), dome, recoil, wall, turret`. Weapons are shots (`n` pellets with `fan`, optional `slow`) or lobbed strikes (`lob`, `flight`).

Map (`m.map`): `key, name, w, d, hw, hd, walls[{x0, x1, z0, z1, h, kind}], rounds[{x, z, r, kind}], bushes[{id, x, z, r}], props, cratePoints, bases[2] = [x, z], spawns[2], nav`, towers[{team, kind: 'main' | 'sub', x, z}], yards[2] = [x0, x1, z0, z1]` (the last two are empty on arena layouts).

  - Hooks beyond the tagged events, all render-side: events the sim does not tag with a skill (`hook, swap, stance, bless, rally, leap, mark, parry, flurry, form, rewind, transform`, and `warp` without a look) go to the look of the owner's row of that kind, or the row pressed last when two rows share it (`rowFor`); a zone of any kind goes to the owner's row that makes it (`zoneLook`; the look lists the kinds in `zones`, default fields whose `vis` is the row's; a strike keeps its warning disc unless `ownDisc`); `land(kit, e, lv, z, row)` replaces the explosion of a strike, decoy or mine drawn by a look; a shot goes to the owner's volley row of the same `vis` and speed (the weapon's when the weapon has a look), through `shotMake(kit, s, row) -> v`, `shot(kit, v, s, x, y, z, dt, row)` (true skips the generic quad) and `shotEnd(kit, v, s, x, z, row)`, and `impact` for its impact event. `kit.follow(u, dur, fn)` runs an aura for a press (a buff, a transform).
- New unit state: `stance` (planted siege mech: no movement, `stanceDef` scales range, damage, armour, turn), `charge` (seconds a charge weapon has been held), `primeT` (next charge shot is instant), `armorT/armorF/reflectF`, `rageT/rageF` (lifesteal buff), `markT/markBy/markAmp/markEx` (marked for execution), `ambushT`. Cosmetics on the unit: `paint, glow, decal` (keys of `PAINTS, GLOWS, DECALS`).
- Weapons: a shot (`pierce`: flies through mechs, `bounce: n`: reflects off walls, `far: {after, mul}`), a lob, `ray: true` (hitscan: heals the first ally on the line or hurts the first enemy; event `ray`), or `charge: {min, max, hold, dmg[2], range[2], width[2], move}` (fills while fire is held, fires a piercing beam on release; events `fire` then `beam`).
- New skill primitives: `stance` (toggle after `setup`), `hook` (a shot with `s.hook`; a hit reels the target in), `swap`, `bless` (ally at the cursor or self: shield, haste, rapid), `rally`, `leap` (`u.dash.fly`, lands with a nova), `mark`, `decoy`, `warp`, `drone`, `wire`, `sweep` (a cast whose beam pulses every 0.2 s while the turret turns at `s.turn`); `buff` also takes `armor, reflect, lifesteal, cost, prime`; `zone` also takes `cage` (enemies inside at cast cannot leave: `z.held` bit per unit id), `follow` (moves with its owner), `pull < 0` (pushes out), `armor` (allies inside); `wall` with `screen: true` stops only enemy shots and blocks nobody's movement. A targeted skill that finds no target returns false from `CAST` and costs 0.4 s instead of its cooldown.
- New zone kinds: `decoy {x, z, aim, hp, maxHp, dur, speed}` (runs straight, looks like its owner's mech, shots hit it, bursts at the end), `drone {range, hps, target}` (orbits its owner), `wire {pts[2], left, delay}`.
- New events: `ray {id, x0, z0, x1, z1, on: ally|foe|tower|none}`, `hook {id, target, x, z}`, `swap {id, other, x0, z0, x1, z1}`, `stance {id, on, x, z}`, `bless {id, to, skill, x, z}`, `rally {id, x, z, r}`, `leap {id, x0, z0, x, z, dur}`, `mark {id, target, x, z}`, `warp {id, x0, z0, x, z}`, `zap {zone, id, x, z}`, `execute {id, by, x, z}`; `impact.on` may also be `bounce`, `screen`, `decoy`; `explode.why` may be `decoy`.

## Modes, themes, online

- Modes are rows in `MODES` (`tdm`, `nha`, `chiem`, `tudo`, `trum`); `createMatch({ mode })`. `nha` adds `m.towers`, `chiem` adds `m.points`, `trum` adds `m.lives` and a `BOSSES` unit, `tudo` gives every unit its own team. `u.color` (0 or 1) is the palette index the renderer and HUD use.
- Team size: `TEAM_SIZES = [1, 2, 3]`, `TEAM_SIZE = 3`, `cleanSize(n)` in `data.js` (anything else, including 4 and 5 from old saves, becomes 3). A match has as many units per side as its roster gives; the solo menu's `size` (saved as `save.size`, `choice.size`, `?size=1|2|3`) makes `main.js` build the player plus `size - 1` allied bots against `size` enemy bots, `2 * size` mechs in Hỗn chiến, and `TEAM_SIZE` hunters against the boss in Săn trùm whatever the pick. Kill target, duration and lives are read from the match (`m.target`, `m.duration`, `m.lives`), never from the menu.
- Layouts come in two pools: arenas (`MAP_ORDER`) for every mode except `nha`, and base-assault layouts (`NHA_ORDER`: `luythep`, `hemcheo`) built around their towers for `nha`. `mapsFor(mode)` is the pool, `fitMap(map, mode)` keeps a choice inside it, and `createMatch` falls back to the pool's first layout when given one from the other pool. A base-assault layout lists its own `towers` and the `yard` they stand in; walls of kind `rampart` enclose the yard. Keep a wall to wait behind near the ring just outside each sub tower's range: without it bot sieges stall (`sim-test` 29z11).
- A theme (`THEMES` in `maps.js`) dresses any layout and decides what the layout's hazard spots are (`lava`, `ice`, `vent`, `mud`). `createMatch({ map, theme })`; `pickArena(map, theme, seed, mode)` resolves `'random'` inside the mode's pool.
- Online rooms hold at most 6 players, 3 per side. The lobby carries `size` (1, 2 or 3, default 3; `online.setRoom({ size })` refuses to go below a side's head count and puts the reason in `online.error`). Humans cap: `2 * size` in team modes and Hỗn chiến, `TEAM_SIZE` in Săn trùm; bots fill each side to `size`. The Relay lobby is created for 6 players, so the room list shows `players / 6` there; `?fakenet=1` rooms publish the real cap.
- Online is host-authoritative: the host steps the real match, guests send inputs and render a mirror match built by `createMirror` and updated by `applySnapshot`. `?fakenet=1` swaps the relay for a BroadcastChannel.
  - Wire: snapshots (every tick, 30 Hz) and inputs are binary (`encodeSnap`, `encodeInputPacket` in `netstate.js`); lobby and control messages are JSON. Scoreboard numbers and the broken-prop mask ride on every 10th snapshot. Event batches ride on snapshots and are sent again only when no ack came back within a round trip.
  - The guest's own mech is predicted (`createPredictor` in `predict.js`): each local tick runs the same `walk()` the host runs, the host answers with the number of the last input it applied, and the guest replays the later ones from the host's position. Dashes, knock-backs and respawns arrive as corrections that the picture glides over. The mech is drawn on its way to where the tick in progress will put it (`pose` peeks one tick ahead with the stick of this frame), so the stick shows in the frame it moves.
  - The guest's own main weapon is predicted too (`createGunner`): a look-alike shot, its muzzle flash and its impact show at once, and the host's copies are swallowed when they arrive. The host still judges every hit. Lobbed shells and skills are not predicted.
  - Everyone else is drawn in the past by one snapshot interval plus the measured arrival jitter (`drawTime` in `online.js`), interpolated between two snapshots. The host time on screen (`drawAt`) only ever runs at 0.85 to 1.25 times the clock: after a stall it catches up instead of jumping, and past the newest snapshot it slows to a stop over `EXTRAPOLATE` seconds. It jumps only when more than `RESYNC` behind.
  - The browser reaches the relay over a WebSocket, one ordered stream: a lost segment holds back everything behind it and the backlog arrives in one burst. `tools/net-lag.js 4g,isp` models that; `lan`, `wifi`, `phone` and `bad` model independent datagrams.
  - The host runs one input per guest per tick, in order (`nextInput`). A tick that finds no input runs the last one again as a guess and remembers where the mech stood (`peer.hold`); the snapshot marks the unit `F_GUESS` and the guest keeps its own prediction instead of taking the guessed position. When the late inputs arrive, `settle` puts the mech back and walks them, so it ends where the guest already drew it, after one late packet or a stall of up to `HOLD_MAX` ticks. Past that, or if the mech died or dashed meanwhile, the guess stands and the guest is corrected.
  - A room is hosted in the Relay region with the shortest round trip from the host (`net/region.js`, cached for a day). Without it Unity answered `us-central1` for a host in Vietnam. A guest measures its own round trips after joining and sends them to the host (`net` message); `fairRegion` names a region that would serve the worst-placed guest at least 40 ms better. Nothing moves the room there yet.
  - `G.online.netStats()` is the readout a player can turn on (default key F8, Settings, or the pause menu): region, round trip to the host (`pg`/`po` pings), jitter, silences, interpolation delay and buffer, how far the picture is behind or ahead, prediction corrections, traffic. The host sees each guest's round trip, input queue and guessed ticks.

## Auto-aim on touch (Addendum 8)

- `js/autoaim.js` is pure (runs in Node). `pickTarget(m, u, prev, opts)` returns `{ kind: 'unit'|'tower'|'zone', id, x, z, r }` or null: enemies only, inside `weaponRange` (or `opts.range`), in line of sight, visible to my team; enemy decoys rank as units, enemy turret zones come next, towers only when nothing else is in range (and only when `towerOpen`). `opts.priority`: `near` (default), `lowhp`, `lowpct`. `aimFor` gives `{ aim, tx, tz }` with lead factor `LEAD` (0.7) on a smoothed velocity (`createTracker`); rays and charge beams aim straight, lobs aim the ground point after their flight. `fireOk` holds the trigger while the turret still swings toward the target. `skillAim(m, u, skill, target)` is driven by `SKILL_MODES` keyed by `do` (dir, ground, ally, self); `pickAlly` finds the most hurt ally.
- The lock is a small state object (`newLock`, `updateLock`, `pinLock`) owned by `touch.js`: kept while valid, dropped on death, range, line of sight or hidden; replaced by a tap on an enemy in the right half of the screen, cleared by a drag-aim. Auto-aim only fills `aim`, `tx`, `tz` of the input, so the turret turns at the mech's rate and spread still applies. A co-op guest runs it on its own client and sends the result like any input.
- Fire button: tap or hold without dragging = auto, drag = manual as before (and clears the lock). Skill tap = quick-cast through `skillAim`, drag = manual. No target in reach = the old behaviour. Mouse input never runs any of it.
- `G.input.lock` is `null` or `{ kind, id, x, z, r }` (the ring and edge arrow in `js/gfx/fx.js`). Settings live in `controls.aim = { v, auto, priority, pad }` in the save; `G.input.layout.get()` reports `autoAim`, `aimPriority`, `padAim` and `layout.set({ autoAim, aimPriority, padAim })` writes them. `padAim` (default off) gives a gamepad trigger the same auto-aim when the right stick is idle.
- `node tools/aim-compare.mjs` plays a scripted touch auto-aim player against a scripted good mouse player in bot matches and fails when touch wins by more than about 5%; lower `LEAD` if it does.

## Shared state `G` (browser)

`G = { THREE, params, quality, bus, renderer, scene, camera, match, me, meta, audio, ui, input, gfx }`

- `G.bus.on(topic, fn)`, `G.bus.emit(topic, data)`. Topics: `sim` (each sim event, payload = event), `match:start`, `match:over`, `ui:play {mech, diff, map, mode, theme, size}`, `ui:menu`, `quality:set`.
- `G.match` is the current match or null. `G.me` is the id of the player's unit.
- `G.project(x, y, z)` → `{ x, y, visible }` in CSS pixels. `G.groundAt(clientX, clientY)` → `[x, z]` on the ground plane.
- `G.portrait(mechKey, team, skin, form, size)` → data URL of a rendered mech portrait in that skin (`js/skins.js` id, null = its own look): 128 px per device pixel ratio, up to 384 px.
- Skins (`js/skins.js`): whole looks per tank graded A / S / SS. `gfx/mechs.js` `build()` is the one place a skin reaches the model (palette over the `STYLES` row, finish, aura ramp, SS sigil disc and lamp pulse). The save holds `ownedSkins` ('mech:id') and `skins[mech]`; the lobby and the roster carry `skin`, cleaned by `cleanSkin()` on every input. The Skin panel opens from the stage's Skin button.
- `G.showcase = { open(el), close(), set(key, skin, form), turn(dx), on }`: the tank select stage. While open, `draw()` in main.js renders only the turning model on its pedestal (`mechs.showcase()`, gfx/mechs.js) into the rectangle of `el`, over the menu's own gradient, with the main renderer (30 fps on phones and on low); the attract match is not drawn. `ui.js` opens it with the menu and closes it for the shop, the online screens and a match. Without `G.showcase` (the UI harness) the stage shows the big portrait instead.
- `G.look = { get() → { brightness, calm }, set({ brightness, calm }), range }`: the "Hình ảnh" settings "Độ sáng" (display exposure multiplier 0.8 to 1.2, live in the composite pass) and "Giảm chớp sáng" (`calm`: second column of `FLASH` in `gfx/fx.js`). Saved in `settings.brightness` / `settings.calm` (`calm: null` = never chosen, then touch devices start with it on). URL: `?bright=1.1`, `?calm=1|0`.
- `G.sharpness = { get() → 'auto' | 'sharp' | 'max', set(mode), modes: [{ key, name, hint }] }`: the "Độ nét" setting, applied live. Stored under `localStorage` key `dtt.sharp.v1` (meta.js drops settings keys it does not know when it loads, so `settings.sharpness` alone would not survive a reload); the player's quality pick is likewise kept in `dtt.quality.v1`.

## Render resolution (Addendum 9)

The 3D buffer is `renderScale(mode, tier, dpr, g)` buffer pixels per CSS pixel per axis (table `RES` in `js/gfx/post.js`), rounded to whole device pixels. `auto` (default): ceiling min(DPR, 1.5) on low and min(DPR, 2) on medium and high, floor 1.0. `sharp`: ceiling min(DPR, 2), floor 1.5. `max`: native DPR, the governor never touches it. `g` (1 to 0) is how much of the range the governor has left. The governor sheds cost in the order of the `steps` table in `main.js` (bloom levels, AO, shadow map size, resolution) and gives it back in reverse; recovery is a probe after a stretch of on-time frames, because a 60 Hz screen never reports frames under 13 ms. Below device resolution the composite sharpens (5 taps, clamped to the local min and max, strength grows with the gap); FXAA runs only at 1.5 or more buffer pixels per CSS pixel. On screens above 100 Hz the loop draws every other refresh.

## Eye comfort (Addendum 12)

The picture is tuned to stay bright, saturated and soft without glare on a bright OLED phone. Per-theme `exposure` and `grade` (world.js) put floors in the mid-tones (calm frame mean at most 0.54, floor cells 0.3 to 0.55); the composite shader (post.js) rolls highlights off after ACES (`uKnee`/`uPeak`, hue kept) and softens saturated highlights (`hiDesat`); bloom has a higher threshold and a lower gain per tier (main.js). Flash lights, glow quads, ground discs and beam cores are scaled by the `FLASH` table in fx.js, with a per-frame budget on the summed flash-light intensity; its second column is "Giảm chớp sáng". `node tools/eyes.js` measures it at the Xiaomi 17T size (calm frame, gentle fight, heavy 3v3, forced overlapping ultimates, tower fight in `?mode=nha`); `--check` enforces the limits in `LIMITS` on every theme with the setting off and on, and fails on a build without the tuning.

## Camera (Addendum 14)

`js/camera.js` owns where the view looks; `placeCamera` in `main.js` only turns the rig's `x, z, yaw` and the height zoom into the three.js camera. Tunables are in `CAM_RULES`.

- **Modes** (`want()` picks one per frame, a change glides over `EASE[mode]` seconds): `follow` (own tank), `killer` (for `CAM_RULES.killer` seconds after a `death` event, if the killer is alive and visible to my team), `ally` (nearest living teammate, kept until it dies), `wreck` (nobody to watch), `free` (the minimap look, `rig.pan({x, z})` until `rig.pan(null)`).
- **Follow**: a dead zone around an anchor, a lead toward the aim and the velocity with its own smoothing, exponential smoothing `1 - exp(-dt / tau)` and a speed cap `vmax`. A 1.2 m bias keeps the tank above the skill buttons.
- **Aim pan**: `longAim(u, G.input.aimState())` returns `{ a, reach }` when a skill with range over `longAim` (16 m) is being dragged, when a cast with such a range is winding up, or when a main weapon with that range that is slow (`cd >= slowFire`) or charged is aimed by hand and held (touch fire drag, mouse button, pad stick). The rule reads the rows, there is no list of mechs. The view slides `(reach - panFrom) * panGain` metres that way, then the offset is clamped so the tank stays inside `inner`. Touch auto-aim never pans; instead a locked target outside `inner` pulls the view until both fit.
- **Half-turned view**: `flipFor(m, u)` is true for team 1 in `tdm`, `chiem` and `nha` (layouts are point-symmetric, bases at the left and right ends). The rig then reports `yaw = π`, `sign = -1`. Everything that turns a screen direction into a world direction multiplies by `G.cam.sign`: stick and keys in `input.js`, drag angles in `touch.js` (`ang`), the minimap (`viewSign` in `ui.js`). Sim inputs stay in world space, so bots, the host and other clients are untouched.
- `G.cam = { heights, sign, panning, get() → { height, aimPan, mode, target, x, z, off [x, z], speed, gliding, flip, yaw }, set({ height, aimPan }), panTo(x, z), panEnd() }`. Saved as `settings.camHeight` (`null` = by screen: tablets `far`, everything else `mid`) and `settings.aimPan`.
